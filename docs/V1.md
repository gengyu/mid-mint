# V1.md

## 目标

第一版的目标不再是验证最小可行链路，而是建立一个可持续迭代的文档转 PPT 服务基础版本。

核心目标：

- 接收一份 `Markdown / Docx / Txt / HTML` 文档
- 将文档解析为结构化内容
- 通过 LLM 完成内容分析与演示规划
- 生成视觉规划和逐页内容
- 渲染为可打开的 `.pptx`
- 将输入、中间产物和输出文件完整保存到项目目录

## 第一版输入与输出

输入：

- `Markdown`
- `Docx`
- `Txt`
- `HTML`

输出：

- 一个 `.pptx`
- 一组可检查、可追踪的 JSON 中间产物
- 一组视觉素材文件

## 第一版主流程

```txt
Document
  -> Parse    负责把原文变成结构化内容
  -> Analyze  负责理解内容主题、摘要、核心信息
  -> Plan     负责决定 PPT 怎么讲、讲几页、每页讲什么
  -> Visuals  负责决定每页怎么视觉表达、生成什么 SVG
  -> Slides   负责把内容规划 + 视觉规划合成为最终页面规格
  -> Render   负责把 SlideSpec[] 渲染成 .pptx
  -> Export
```

## 第一版必须覆盖

- 创建项目
- 保存原始输入
- 支持 `Markdown / Docx / Txt / HTML`
- 生成 `parsed-document.json`
- 生成 `content-analysis.json`
- 生成 `deck-plan.json`
- 生成 `visual-plan.json`
- 生成 `slide-specs.json`
- 生成视觉素材文件
- 生成最终 `.pptx`

## 第一版当前不做

- 单元测试、E2E、eslint、prettier 整治
- BullMQ / Redis / 异步队列
- Reviewer / Auto-fix
- Export 独立模块
- Repository 层
- TypeORM / PostgreSQL
- PDF / Notion / Confluence 导入
- 在线预览编辑
- 复杂权限、认证、审计
- 复杂 HTML 截图链路
- 为未来扩展预埋大量抽象

## 技术原则

- 文档链路优先
- 文件系统优先
- 中间产物可检查优先
- 优先使用成熟开源框架和库
- 模块边界清晰优先
- 先完成第一版闭环，再扩展高级能力

## 第一版验收标准

项目目录中至少出现：

```txt
input.*
project.json
parsed-document.json
content-analysis.json
deck-plan.json
visual-plan.json
slide-specs.json
assets/
output/<title>.pptx
```
